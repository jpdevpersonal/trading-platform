# Milestone NN — Title

Record the milestone ID, specification version and status.

## 1. Objective

State the observable outcome for the user.

## 2. Dependencies

List earlier milestones, tools, decisions, and any genuine external prerequisites.

## 3. In scope

List the features and implementation work authorized by this milestone.

## 4. Out of scope

List deferred work and project-wide boundaries relevant to this milestone.

## 5. Technical design

Describe components, interfaces, dependencies, data ownership and operational behavior. Link relevant architecture decisions.

## 6. Deliverables

List required files, projects and observable behaviors.

## 7. Acceptance criteria

| ID | Requirement | Pass condition and evidence |
| --- | --- | --- |
| MNN-AREA-001 | Required | Specify an observable outcome and how to verify it. |

Use stable, unique IDs. Mark scope as Required or Optional, and record verification separately as Pass, Fail, Blocked, or Pending. A blocked required check keeps the milestone incomplete until the dependency is resolved or the owner changes scope.

## 8. Testing

List automated commands, manual checks and architecture review.

## 9. Definition of done

State the required evidence, review and merge conditions.

## 10. Completion report

Record changes, command outcomes, evidence by acceptance ID, unresolved issues and any follow-up work.
